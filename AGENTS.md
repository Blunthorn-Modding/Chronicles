# Chronicle workspace

Read `docs/CHRONICLE_PROJECT_OVERVIEW.md`, `docs/DECISIONS.md`, and `docs/TEST_PLAN.md` before changing architecture. The original overview is a brief, not implemented behavior.

- Current design authority: `docs/THE_QUIET_BELOW.md`, `docs/MAP_AUTHORING.md`, `docs/DEVELOPMENT_MILESTONES.md`, `docs/BACKLOG.md`. Latest operator instruction authorizes milestone design followed by implementation until a necessary decision or hands-on review. No prescribed event/session outline: engineering milestones must not become narrative gates. The operator handcrafts the production map; agent maps are test fixtures. Unsettled ecology/lore details remain proposals.
- Latest feedback rejects mine-support physics and mandatory mundane substitutes. Draft benefits now use actual crop growth, local regeneration and powered Ancient Forge recipes, with increasing place-based costs and no personal corruption. Shared in-world selection/regions/locations/block anchors/chest/spawn authoring belongs in Core; Quiet Below consumes it. World-copy/import is not the primary authoring workflow. Reference inspection: `docs/REFERENCE_VAMPIRE_SMP.md`.
- Subsequent feedback accepts the map-authoring direction for now and rejects authored sculk routes/patches or GM-gated benefit reveals. Growth must discover actual cave/mine geometry from the city, feeding on air/sunlight; only key locations need registration. Remove the Ancient Focus role, use visible growth/catalysts/sensors and possible extensive-stage shriekers. A sufficiently weakened Relic Heart can be destroyed to eradicate the entire campaign network, including source growth and detached branches. Ecology details/cleanup remain design work, not implemented M4 features; see QB-08/QB-13.
- Framework format direction is in `docs/CAMPAIGN_FORMATS.md`: Survival, Journey, Werewolf and Situation (“Happening”); Operation/Intrigue are proposed additions. Journey uses a contained world per session with 2–3 outcomes influencing the next world. Quiet Below's no-forced-factions policy is campaign-specific, not a ban on Werewolf. Do not implement new modes from this taxonomy without a scoped plan.
- Use scoped Git branches and coherent commits with tracked QB work IDs. The operator requested GitHub workflow; push requested work on scoped branches, review diffs/evidence, and keep main merges separate. Never fabricate milestone history or include runtime worlds/tools/credentials.

- Source/configuration/scripts belong in this repository. Its parent `MC RP` contains portable tools, caches, server worlds, client packs, backups, reports, and disposable test worlds. Keep generated runtime data outside Git.
- Target Minecraft Java **1.21.10**, Fabric, **Java 21**. Pins live in `bootstrap.lock.json` and `gradle.properties`; update together after compatibility checks.
- Two mods: `core` (`chronicle_core`) and `campaigns/quiet-below` (`quiet_below`). Client code belongs under `src/client`; common code must never import `net.minecraft.client`.
- M1 provides sessions/persistence/flags/events/audit and native tick freezing/actionbar. Only ACTIVE unfreezes simulation; players stay mobile. M2 adds public owner-editable dossiers. M3 adds the lens/marker asset pipeline; M4 keeps bounded stages and journals in the campaign package. M5's separate pilot awaits group playtest. Read each milestone specification; do not generalize campaign stages into Core.
- M6 adds Core-owned metadata authoring (`core/authoring`, `server/Authoring*`): non-active operator author mode, per-player selection, regions/precise locations/expected-type anchors, private previews and strict revisioned persistence. Read `docs/M6_IMPLEMENTATION.md`. M7 refines persistent private previews and a typed mod-registered clickable author menu, and adds Core empty-only chest transactions/manual safe player moves; read `docs/M7_IMPLEMENTATION.md`. The operator accepts outline/menu refinements but replaces capture-first loot authoring: use Core registered loot types and one-step target/type binding, server JSON independent percentages/defaults/recommended counts, new-session and optional ACTIVE occupied interval fills that replace ALL bound loot contents. Read `docs/M7_LOOT_TYPES.md`; old capture data is legacy compatibility only. Entity groups, automatic respawn and triggers remain pending; no automatic sculk. Grown-shrieker Warden summoning/warnings/despawning must follow vanilla; air/light is exposure feeding without oxygen depletion/suffocation, per confirmed operator answers.
- CF-09 adds the proper Core authoring screen: O (rebindable), bare `/chronicle author`, `/chronicle author chest` and `/chronicle spawn`. Read `docs/CF09_AUTHORING_UI.md`. Chests/Places/Roles/Spawns/Session reuse existing services and schemas through operator-checked finite actions, private bounded snapshots and stale-frame rejection. Keep commands as advanced fallback (`author menu`, `author chest types`); do not expand chat as the primary interface. Author mode still clears on reconnect/ACTIVE. Loot distributions remain JSON; custom IDs, entity groups and automatic respawn are outside this screen slice. Practical screen review is the next authoring gate.
- Commands from repository root: `python scripts/workspace.py setup`, `build`, `deploy`, `verify`, `smoke`, `backup`, `doctor`, `client`. PowerShell: `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/workspace.ps1 <action>`.
- When leaving the play server running through `exec_command`, use `tty: true` so console input stays available. Use `write_stdin` for Minecraft console commands and `stop` for a saving shutdown. Verify the ready log before handing it back.
- Offline checks: `python -m unittest discover -s scripts -p "test_*.py" -v`; `git diff --check`. Build uses child-process-only workspace JAVA_HOME/GRADLE_USER_HOME.
- `smoke` creates a fresh `../test-runs` world, uses loopback TCP 25575/UDP 24455, and runs two matching offline Fabric development clients plus a content probe. It launches graphical windows and needs a desktop/OpenGL context. `content-smoke` runs only the M3 content probe; `legacy-smoke` retains historical Mineflayer checks that cannot join M3 custom registries. Never change the play server's authentication for a test.
- `stage-smoke` rehearses bounded stages; `pilot-smoke` tests a disposable copy of the latest prepared pilot. Run suites sequentially on their shared test ports. Pilot preparation/start use fresh `../pilots` roots and authenticated loopback TCP25585/UDP24465; never build their map in the play world or force-load chunks for stages.
- EULA acceptance belongs to the operator; never toggle eula=true without explicit authorization. Never read/copy launcher tokens. Real Fabric rendering, GUI, audio and account tests remain distinct from bot checks.
- Do not open firewall/router ports, publish, push commits, change machine-wide settings, install hosted agents, or expose a server unless requested. Tests need no external LLM service.
- Preserve existing configs/worlds. Stop before deploying or backing up. Restore into a fresh directory and inspect before promoting. Never recursively clean worlds as a routine fix.
