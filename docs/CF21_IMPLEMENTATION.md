# CF21 paired Area changes

**27 October editor update:** The current editor places Start/End snapshots under the Region Saved states subtype. All Region creation/editing uses the same Debug shovel and `/chronicle region save`; old Area commands remain compatible. Standalone navigation below describes the original dev55 implementation. See [current implementation](EDITOR_SUBTYPES_IMPLEMENTATION.md).

Implemented on `feat/core-roles-areas-departures` for the combined dev55 review; human acceptance remains pending.

Advanced → **Area changes** owns the capture/apply workflow. **Create new area** is above the middle list. Creation chooses a name and Start/End, closes the menu, and privately lends a tagged Debug shovel. Left/right click select the two corners; `/chronicles author region pos1` and `pos2` remain equivalent. `/chronicle area change save` verifies loaded terrain and publishes one ordinary Core Region plus the initial immutable snapshot. Cancel restores the previous private selection when it has not independently changed. A moved or copied stale shovel has no authority.

The selected record offers **Save current area state**, private preview, reviewed application, and deletion. Recapture is permitted to an operator during ACTIVE play as specified in the approved UI design; initial creation and deletion require non-active Editing. Each deliberate application receives a new operation UUID. Deletion chooses Start, End or unchanged, lists departure consumers, and retains the Region, history and tombstone. Missing or changed Region pins make captures unusable; unchanged deletion remains available. Definitions never silently acquire different bounds.

`AreaChanges` handles loaded-only selection/capture and cross-store publication. Pure `areas` types own bounds, immutable palette snapshots, content-addressed payloads, catalog/tombstones and operation evidence. The native `WorldAreaOperations` service takes an interaction-blocking hold before closing viewers or reading target contents. Capture, verification and writes use bounded cell batches. Immutable target-before and template-after snapshots and hashed side effects precede mutation. Exact before/after comparison permits retry; third states remain held. Main progress receipts follow an explicit flushed world save. There is no blind region rollback.

Managed instances use a preflighted before/after ledger and quotas calculated from removals plus additions. Shared chest schema 4 retains schemas 1–3 compatibility and adds explicit area-removal claims. Actual target lore tokens are reserved in the same book ledger; first discovery survives replacement, kept-copy location becomes absent only after the durable world result, and only explicitly removed bindings retire. Source captures reject managed lore, unresolved vanilla loot and unsupported block entities. Target-before capture preserves raw unresolved loot IDs without rolling them.

Core has typed campaign policy, exact-block capture adapters and template-state normalization. Quiet Below rejects Heart cloning/removal, refuses ecology maintenance/eradication conflicts, checkpoints observed ownership, and resets captured station heat and sculk feature transients. Ordinary block writes still pass through ecology observation; ownership is not copied from a template. Players/entities and Chronicle transaction identities are never copied.

Initial limits are 262,144 cells, 512 blocks per axis, 64 chunks, 64 MiB decoded data, 128 definitions and 4,096 operations. Missing chunks defer/refuse without force-loading. These bounds have pure storage tests; maximum-volume native capacity/latency has not been certified. Completed payloads and failed evidence are retained. Uncommitted review payloads are harmless immutable orphans rather than being deleted where an uncertain irreversible departure might still reference them.

Immutable payload/receipt creation cannot overwrite an existing path. Mutable journals check their observed bytes immediately before atomic replacement, but filesystem rename is not compare-and-swap against a non-cooperating external writer. World journals must be edited while the server is stopped; simultaneous external writes are outside this store's writer protocol.
