## Player workflow

Place the supplied Ancient Forge block. It functions intrinsically; Locations registration is optional context, never activation. Right-click opens a compact workshop screen explaining power, the target in the main hand, the ingredient in the offhand, and the exact resulting enchantment. A single explicit Enchant confirmation changes the held target and consumes the displayed ingredient. Closing the screen transfers nothing. Unsupported targets, missing ingredients, incompatible enchantments, already-sufficient levels and lost power give a concrete reason and consume nothing.

Initial default mappings: echo shard -> Sharpness I; amethyst shard -> Unbreaking I; prismarine shard -> Protection I; flint -> Power I; feather -> Feather Falling I. Each consumes one ingredient, with no additional XP price or work timer. The reusable Core configuration can replace/disable/add mappings and set their granted levels; universal caps and native compatibility still constrain every result. Combining identical ingredients never raises a level. Plain books may become enchanted books if their unrelated components can be retained; existing enchanted books use stored enchantments. Equipment uses active enchantments and retains durability, count, name and all unrelated components. Only one target item is processed; stacked targets are rejected rather than losing or splitting components.

## Power and safety

Quiet Below requires ACTIVE, occupied/unheld play, a living configured Heart/network, Established or Extensive extent, and actual adjacent loaded, owned, Heart-connected sculk at25%+ vitality. Recheck physical state, player eligibility/distance/dimension, station identity, selected hotbar slot, exact item components/counts, current recipe/cap policy and power at confirmation. No force loads, relay nodes, global world/station scans or sculk block entities. Survival/Adventure participants can craft; Creative may inspect but does not bypass inputs/power or create bargains.

Core owns strict namespaced recipe registration/configuration, bounded offers, one-use confirmation tokens and the component-preserving inventory transaction. Quiet Below owns power checks, default mappings, sounds and supplied models. Server callbacks run on the main thread; consume the one-use offer before attempting it. Repeated/stale/concurrent clicks cannot duplicate output. Replace the target in its original slot and decrement the original ingredient stack in one ordinary server inventory operation; no escrow, item drops or full-inventory dependency. A disconnect/restart/expiry invalidates an offer, never retries a craft. Standard player saving persists completed inventory changes; do not claim cross-file crash atomicity beyond vanilla inventory persistence.

Use the user's original idle/kindling/active Forge exports and namespaced textures; preserve parent sources. Facing and collision must be explicit, with no model-derived collision assumption. Transient working feedback returns to a truthful ready/unpowered state after rechecking power. Deferred/unloaded state must never appear to promise a craft.

The exported decorative rims extend3 pixels into neighboring cells and the top reaches19 pixels. Collision is explicitly the base16-pixel cube; the selectable outline includes the decorative overhang. This keeps neighboring walking cells clear. PNG transparency uses the native cutout layer. Three original textures are copied without recoloring; only JSON texture references/metadata are adapted. Provenance hashes are retained outside Git at `../reports/qb12-forge-asset-provenance.json`; parent exports remain untouched.

One no-inventory block entity identifies each Forge. A loaded-only1024-entry tracker checks up to8 station appearances per server tick (at most6.4 seconds for a full tracker at20TPS); this continues while world simulation is paused. Power is rechecked synchronously on use/confirmation. Chunk loading resets saved transient heat directly through the callback's chunk, including unadmitted stations, before ordinary model polling. Over-capacity stations refuse use until capacity is available. There are no Forge chunk tickets or retries of an inventory transaction.

`config/chronicle/ingredient-enchantments.json` schema1 contains a complete `recipes` list with `id`, `group`, `ingredient`, `enchantment`, `level`, `count`, `enabled`. Quiet Below's group is `quiet_below:forge`; each group/ingredient pair is unique. The server may override up to256 entries, with1..255 granted levels and1..64 consumed items. Native maximum and the current universal cap still limit grants. Missing configuration is created from registered campaign defaults; an existing empty list disables all mappings. Malformed config disables workshops and preserves the file; repair it, then use Game setup > Ingredient enchanting > Reload recipes JSON. No new config is applied to open offers; reload invalidates them.

## Verification and review gate

Pure recipe/config tests cover duplicate/invalid IDs, strict schema/limits, existing-file precedence, disabled recipes and failed/concurrent saves. Native tests cover compatible and incompatible targets, books, components/durability/names, cap overrides, exact ingredient consumption, already-sufficient enchantments, full inventory, changed slots/inputs, stale/double/simultaneous confirms, distance/pause/cut/missing station and reconnect/restart. Actual clients must render every facing/state and workshop controls at GUI2,640x480/1280x720. Keep existing worlds/dev27 pack untouched until stopped backup and a matching station build are verified. Bundle Forge appearance/workflow/recipe balance with caps review; completion of code alone is not a stopping gate.
