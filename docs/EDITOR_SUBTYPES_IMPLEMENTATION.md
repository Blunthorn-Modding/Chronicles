# Editor subtype implementation

User-approved scope, 27 October 2026; branch `feat/editor-region-location-subtypes`.

Core preserves authoritative geometry, Area snapshots/operations and departure histories. A public trusted subtype registry maps independent capabilities to Region/Point/Block-site kinds; handlers retain their own existing authoritative stores. Its built-ins derive Saved states from the Area catalog and Departure from the departure catalog, avoiding a duplicate geometry/tag ledger. Future handlers can coexist. Capability edits and state capture require live OP non-active Editing and no operation hold; registry definitions freeze at server start.

ALL Region creation and editing now use the unified private Debug-shovel / pos1 / pos2 selection and explicit `/chronicle region save` flow. Creation defaults to ordinary geometry and may optionally capture an initial Start or End state. Legacy commands route the same authority; temporary tools have owner-token inventory/drop/swap protection, conditional cleanup and safe return.

Region activation creates an empty state record for the existing Core Region. No-op geometry saves preserve revision and both states. Before a changed bounds save, a server-owned 30-second review pins the actor, exact draft, original Region, saved states, catalog revision and affected consumers. The menu confirms that review; in-world `/chronicle region save` warns without writing and `/chronicle region save confirm` consumes it. Changed proposals must be reviewed again. Legacy raw replacements with Saved states direct the author to this flow. Explicit reviewed recapture after geometry changes publishes the new pin and chosen snapshot only after verification, invalidating the other state; old immutable payloads/history remain. Removing the capability keeps the Region, requires Start/End/unchanged review, and leaves referenced departed configurations unresolved. No force-load or transaction shortcut is added. Region deletion must first remove active state capability. Preview shows only current bounds.

Locations retain Points and Block sites; physical Departure activation remains a bound block. The departure editor opens from Locations, retains a single popup, and selects only one boarding Region. A state, if chosen, must belong to that Region's Saved states capability. Legacy mismatches remain stored but refuse new departure review until deliberately repaired; committed operations continue pinned recovery. Missing Region state records remain visible for safe removal/repair; unbound defaults/missing controls remain visible as pending Location entries instead of silently creating or deleting endpoints.

The native menu wire advances to v5. Old standalone pages remain compatibility values/commands, redirecting to geometry pages; they disappear from navigation. New subtype picker uses typed entries and explicit desired IDs. Removal needing world-state review routes the existing durable removal workflow. Extension handlers are trusted server code, preflighted before dispatch, and retain individual durable boundaries; no cross-mod atomic transaction is promised. Region/Location creators stay above lists, reverse Region assignment and duplicate detail creators disappear.

Assigned gear and available items are separate views with draft/quantity/component preservation. Existing role grant/movement/capacity/once-only semantics remain unchanged. Native regression exposed a pre-existing null lookup for unassigned accounts after a role catalog edit: roleFor now returns no role before consulting the sorted map, and unexpected menu-detail exceptions receive a server log and a nonempty user message.

Verification: pure empty-state/recapture/revision failure tests; capability/payload/view authority tests; full Java/Python build; sequential real Region create/enable/preview/capture/apply/rebase/remove and Location create/subtype/popup/legacy repair tests at desktop/compact sizes; existing roles and group departure recovery regressions. The authenticated review now runs dev57 with its saved world retained, a verified stopped backup and a matching client pack; see TEST_PLAN for exact evidence and limits. No main merge. The original reported stuck outline remains open and is not claimed fixed by this reorganization.
