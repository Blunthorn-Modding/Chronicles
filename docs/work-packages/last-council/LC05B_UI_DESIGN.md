# LC05B foreign affairs — UI proposal

Status: owner approved the workflow on 18 November 2026 after re-reviewing the refreshed site. Native implementation is authorized; the prototype itself is not implemented gameplay. [Interactive prototype](../../design/last-council-foreign-affairs.html). Northreach and its history are illustrative fixture content, not canon.

## Workflow

- An operator in non-active **Editing Game setup → Foreign realms** creates or edits reusable named realm definitions, with name and description. Internal IDs are generated and hidden. Definitions belong to the existing reusable profile/server-content workflow; diplomatic state and public history belong to the world. New realms start **Not at war**, without implying a peace treaty. War is shown as **At war**. An unused realm can be deleted after confirmation; deletion is refused when motions or diplomatic history reference it. No realm editor or state override is available during active play.
- The ordinary motion lectern offers **General**, **Declare foreign war**, and **Make peace**. The foreign realm selector appears only for the latter two, with eligible realms shown by current state. The proposal names its target and consequence. Player proposals follow existing sponsorship and Chancellor agenda admission; the Chancellor may prepare motions using the existing route. The Chancellor opens and closes the ballot through normal proceedings; there is no direct diplomatic-state button.
- Owner-confirmed war and peace rule: two-thirds of the electorate captured when the vote opens (`ceil(2N/3)`; six of eight). This supersedes the brief's proposed majority default for foreign peace. A passed vote changes the selected realm's public diplomatic state and appends public history once. Failed and void ballots make no diplomatic change. Repeated close, retry or restart must not reapply an old result or overwrite a later decision.
- The existing public **Conflicts** registry gains a **House conflicts / Foreign affairs** filter and retains list-left/detail-right. Foreign detail shows realm name, description, current state and public history. It is accessible through the existing public registry entry; no personal-menu tab is added. House peace and ceasefire remain voluntary agreements signed by all current houses, separately from these Council motions.
- The motion and proceedings screens shown are reuse context, not a redesign. Layout follows the existing compact Council frame: creation above the list, focused edit/draft/confirmation dialogs, ordinary text for read-only information, responsive stacked list at narrow widths and scrolling within bounded surfaces. Reviewer-only surface and actor controls sit outside the frame. No inventory-style or black read-only text fields are proposed.

## Failure and acceptance expectations

These are requirements for implementation, not claims that the prototype or native code satisfies them. Check permissions, session phase, revision and target eligibility on the server at submission and again at each consequential transition. A stale edit or unavailable realm must be rejected with a clear refresh/review message and preserve the entered draft where feasible. Pin the target realm diplomatic revision at motion preparation or submission, revalidate at vote opening and result application, and detect intervening changes even if the status returns to its earlier value. If another decision changes a realm before a passed result is applied, do not overwrite the newer state; surface a recoverable conflict for review. The exact recovery path needs implementation design; it must not silently manufacture an outcome or allow a direct override. An uncertain save must report uncertainty rather than success; retries/recovery need durable idempotence across restart. Public views must reflect only committed state and history.

Verify operator/non-active gating and profile export/import/restart, generated IDs and duplicate/stale saves; conditional selector and empty options; player proposal/sponsorship and prepared motion paths; captured electorate and confirmed thresholds; successful, failed and void outcomes; duplicate close/restart and intervening state changes including war then peace ABA; referenced-realm deletion refusal; public registry/history; and normal and compact geometry. Check existing general motions and house-conflict/treaty flows remain intact. Localize new UI text using existing conventions.

## Review paths

1. Choose **Operator · Editing → Game setup**, create a realm, edit it, and inspect the generated-name-only workflow. Switch to Operator · Active to see the editing gate.
2. Choose **House representative → Motion lectern → Propose**, select each category and observe the conditional target. Submit a foreign war, sponsor it in the fixture, switch to **Chancellor → Proceedings**, admit it, open the vote, set the reviewer tally to 6 of 8 yes outside the game frame, then close the ballot. Inspect the foreign-affairs public record.
3. Prepare a peace motion in proceedings, pass it and inspect history. Repeat with a 5-of-8 reviewer tally or a void ballot to see unchanged state. General motions have no realm selector or diplomatic effect. The external tally selector simulates votes; the in-game close action records the result.
4. With a foreign motion open, use the external **Simulate intervening war then peace** control before closing. The revision mismatch produces a pending-review result without overwriting the newer record, even when the status matches. Create an unused realm and delete it; a realm with a motion reference or history is refused.
5. Select **House conflicts** in the public registry to see the explicit separation from foreign affairs. The real house register remains the LC05A interface.

No armies, resources, map, PvP changes, forced winner or Council control of voluntary house peace are proposed. Active treaty amendments and realm treaty ratification are outside this slice. Foreign peace is presented as a diplomatic state change, not a treaty-signature substitute.

## Proposal verification — 17 November 2026

The dedicated UI agent refined the proposal after lead review: neutral initial state, external-only tally simulation, pinned realm revision including intervening war/peace, referenced deletion refusal and world-owned history. Installed Edge through the cached Playwright CLI passed 31 focused checks with no page errors, including both two-thirds outcomes, failed/void results, stale decisions and compact frame/dialog bounds. Evidence: `../reports/lc05b-prototype-validation.json`; screenshots and replay are under ignored `output/playwright/foreign-*`. The lead inspected the normal record and compact dialog captures. This validates the interactive proposal only. The owner subsequently approved this workflow on 18 November. Multiplayer, persistence and result-recovery behavior are not certified by these browser checks.
