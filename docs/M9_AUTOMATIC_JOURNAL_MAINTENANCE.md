## Persistence protocol

1. Server thread captures immutable setup/area/Heart pins and seals appends on the current journal; the world session lock remains Minecraft-owned. No full replay, large copy or checkpoint construction runs on this thread.
2. One owned background worker copies exact source bytes through a sealed read lease to a unique snapshot, reopens/replays it independently, builds/reopens a checkpoint and compares exact durable engine state. The worker never accesses live engine/world/chunks. A checkpoint must save at least4KiB. Its discardable writer has a pre-write byte/entry budget; a larger checkpoint is an expected no-saving result, not an operation failure. Input still replays and validates fully.
3. For an effective replacement, retain a verified exact original archive, recheck the sealed source fingerprint/size/revision, close the Windows-pinned old handle, atomically replace, reopen and verify. No non-atomic fallback, blind rollback or retry. No-saving jobs retain the original and remove only their own temporary candidates.
4. Server thread installs only the new journal handle into the existing live engine. Keep transient frontier/graph/Heart state, work budgets and control revision; do not emulate a restart. Then replay queued chunk invalidations/revalidate contacts and release this hold only. Any failure preserves evidence and holds the runtime for inspection.
5. Clean shutdown joins an in-flight worker in SERVER_STOPPING before Minecraft releases its world session lock; no worker may continue writing after world ownership ends. Abrupt termination leaves either a strict old journal or a complete atomic checkpoint with the archive retained. Startup uses the existing strict reader.

After an attempt, require another8MiB or12500records before retry, preventing repeated full scans of irreducible source-index evidence. Quiet-period retries also use a5-minute tick cooldown; the hard threshold bypasses that cooldown when enough new history exists, preserving storage headroom. Failed attempts never retry automatically. Technical thresholds are internal maintenance policy, not additional gameplay settings. Offline `ecology_maintenance.py` remains independently guarded and unchanged.
