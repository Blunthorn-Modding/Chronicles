# Custom loot table creation (dev59)

The Loot Tables page gains Create new loot table above its list. The native popup asks for a name, optional namespaced ID and description. Leaving ID blank derives chronicle_core:loot_<name>. Cancel/Escape writes nothing; explicit Create atomically saves an empty table with recommended count0 and no periodic refill, selects it and opens its existing editor. Items/books use the shared Add popup and the existing whole-table Save. No chest fills immediately.

This is entirely Core library functionality. The frozen campaign default registry stays immutable; custom definitions persist in config/chronicle/chest-loot.json. Creation cannot replace an existing default/custom ID. Storage uses the same observed-byte external-change check, forced atomic replacement and valid backup as editing, retaining unrelated definitions, components, books, schedules and receipts. Operator2, non-active Editing and operation-hold checks remain authoritative. Background changes make the popup stale; failed creates retain its fields. Catalog limit128 and file limit2MiB apply. Menu transport advances to v7; matching dev59 client/server required. Delete/rename and new recipe/UI frameworks are outside this addition.
