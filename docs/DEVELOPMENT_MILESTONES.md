## M6 implementation contract

Authoring UX checkpoint: [CF-09](CF09_AUTHORING_UI.md) adds the requested proper Core screen before further M7/M8 authoring expansion. It consumes the existing catalogs and services, with no campaign-specific editor or new ecology. The operator accepted the screen and requested the flicker fix with the next feature review. JSON distributions and advanced custom IDs remain supported separately.

**User flow:** `/chronicle author mode on`, select corners at feet or explicit coordinates, save a region; stand and save a location with facing; look at an existing block and bind its expected registry type. Inspect/list/validate/remove or explicitly replace. Commands require operator level 2 and author mode for modifications. Author mode is per-player, session-local and cleared on disconnect or when play becomes ACTIVE; story phase must be non-ACTIVE to enter/edit. Mode off remains available as an exit at any time. Read-only inspection remains possible during play. No saved geometry activates a trigger, sculk or spawn.

**Data/API:** Core `authoring` domain contains immutable integer block positions, inclusive normalized cuboids, finite precise points with yaw/pitch, expected-type anchors and a revisioned registry. IDs are shared across types, bounded lowercase names; dimensions/types are namespaced registry IDs. Every successful save/replace/remove increments the world revision, with per-definition revision for future bindings. Future consumers must pin definition revision and disable stale references, not follow a silently moved site. Regions do O(1) membership checks, never enumerate their volume. Selections belong to individual players and cannot cross dimensions. Define absent/new versus replace explicitly; removal requires an existing ID.

**Storage:** `<world>/chronicle/authoring.json`, independent of campaign progress/profiles, schema 1 with strict bounded validation, atomic durable replacement and previous `.bak`. Load failure disables authoring and preserves evidence; no empty fallback overwrites data. Mutate memory only after durable save. No migration of old campaign cuboids and no changes to existing state files. Saving definitions validates dimension, world-border/build bounds and loaded block-anchor type without loading chunks; read-only validation reports unloaded anchors as unresolved rather than missing. Region metadata can span unloaded chunks.

**Presentation:** bounded builder-only rendered outline and textual dimensions/coordinates; points retain exact facing and block anchors retain expected type. A block target has a short explicit raycast range. Selection commands are the first input method; a click selector can follow usability review without changing the persisted contract. No custom campaign asset or client-only class in common code.

**Verification:** pure geometry/ID/finite-value tests, strict persistence restart/backup/corruption/future-schema/failing-save checks, revision/replace/delete invariants; `python scripts/workspace.py build`, scripting regression tests and `git diff --check`. Real Fabric smoke exercises commands, non-GM rejection, builder-only inspection, no block/inventory changes, disconnect isolation and restart persistence. Human review checks visibility and practical selection in a real client before declaring M6 accepted. Chest templates/spawn actions and generic condition delivery remain M7/M8, not missing promises within M6.
